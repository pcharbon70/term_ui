# Historical project records

Everything under `notes/` is a historical planning, research, review, feature,
or implementation record. These files preserve why work was proposed and what
was believed true at a point in time. Their status boxes, test counts, API
examples, support claims, and architectural decisions are snapshots and may no
longer describe the 1.0 code.

Use these sources for current behavior:

- `README.md` for the public overview and support contract;
- `guides/component_system.md` for the two component integration models;
- `guides/user/` and `guides/developer/` for current usage and internals;
- `docs/widget-compatibility.md` for backend and character compatibility; and
- public module documentation generated by ExDoc for exact APIs.

When a historical record conflicts with those sources or executable code, the
current guide/module documentation and code take precedence.
